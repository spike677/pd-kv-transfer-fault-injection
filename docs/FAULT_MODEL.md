# 故障定义：PD_KV_TRANSFER_INTERRUPTION

| 字段 | 当前定义 |
|---|---|
| 项目性质 | 独立实验工具；有损故障注入 |
| canonical 模式 | RET_NEG1 / TRANSPORT_RETURN_FAULT_EMULATION |
| 目标 | Decode worker 的 Mooncake KV接收接口 |
| 触发行为 | 当前接收调用不执行真实同步读取，代理返回 -1 |
| 下游行为 | 原生connector产生两层错误日志和RuntimeError |
| 推理影响 | 可能改变输出、请求失败、卡住或触发重算；依赖版本和错误传播实现 |
| 当前证据 | 19项离线测试；精确源码原生方法＋CPU传输夹具；B/F/R通过 |
| 在线输出变化 | NOT_TESTED，不宣称已证明 |
| 支持版本 | Ascend 99e1ea0，普通connector，源码SHA256严格匹配 |
| 不支持 | 当前main/hybrid、共享多租户、未验证的多D-worker部署 |

## 和以前的工具区分

| 类型 | 是否改变执行 | 本项目是否属于 |
|---|---|---|
| LOG_ONLY / FAKE_LOG | 只打印标记，真实传输继续 | 否；此独立项目不提供LOG_ONLY模式 |
| 算子/张量数值注入 | 改变计算输入、输出或状态内容 | 否；不直接修改activation、logits、sampler |
| Connector故障 | 主动抛异常，进入原生handler | 可选 CONNECTOR_FAIL 模式 |
| 传输返回值代理 | 不执行目标读取，让原生代码收到 -1 | **默认RET_NEG1** |
| 物理网络故障 | 断网、停止P、破坏真实链路 | 否；不执行 |

因此它不是“给健康推理多打一条错误日志”。目标KV读取被阻断，但这仍然是
受控代理，不是证明底层网络真的断了。不要伪造ADXL/HCCL连接错误作为证据。

## 旧版行为特别提醒

锁定版 `_handle_request` 在异常后仍可能将请求标记为finished。
F组传输夹具调用0次、目标buffer不变，但finished集合仍包含请求。
这是观察到的原生行为；不能从中推出一定重算、一定HTTP500或必然输出乱码。

在线实验必须先通过正常P/D通信，再检查本次命中、原生日志、实际完整响应和
干净重启恢复。当前设备环境的正常Mooncake传输有重复设备IP阻断，尚未通过。

## 停止条件

无健康无注入基线、版本不匹配、目标不明确、其他任务占用、服务错误或恢复失败时，
停止推进。默认关闭，一次arm最多一次claim；不无限all-hit，不自动修改公共环境。
disarm无法撤销已发出的异常，不能把它当作服务已恢复的证明。
